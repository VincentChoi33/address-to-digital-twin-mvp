스크롤하면 job이 진행된다

각 단계는 실제 제품에서 하나의 job stage다. 오른쪽 simulation은 현재 stage에 맞춰 상태가 바뀐다.

Stage 01

주소 입력을 job spec으로 고정

사용자는 도로명, 지번, POI, 자연어 요청을 그대로 넣는다. 시스템은 목표 LOD, 반경, export 포맷까지 작업 단위로 정리한다.

query intentLOD targetexport format
Stage 02

Juso/VWorld 후보를 공식 주소 계열로 수렴

도로명/지번 후보가 같은 PNU/필지 계열로 모이면 다음 단계로 간다. 모호하면 자동 확정하지 않고 후보 선택 상태로 남긴다.

JusoVWorldcandidate confidence
Stage 03

PNU, 필지, target footprint를 anchor로 선택

좌표는 시작점일 뿐이다. 실제 2.5D twin은 공식 필지 경계와 대상 건물 footprint를 기준으로 생성된다.

parcel boundarytarget footprintlocal meter frame
Stage 04

공식 footprint 위에 2.5D preview 생성

건축물대장 속성과 높이/층수 추정치를 적용하고, 위성·항공·현장 이미지는 texture와 검수 근거로 사용한다.

extrusionroof texturesurrounding context
Stage 05

QA gate 통과 후 URL과 package 배포

source manifest, confidence, mismatch, limitations를 남기고 preview URL, QA report, export package로 전달한다.

manifestQA reportexport package

결과물은 화면 하나가 아니라 패키지다

고객은 preview만 받는 것이 아니라, 원천·신뢰도·검수·export 경로까지 같이 받는다.

01

Preview URL

브라우저에서 바로 보는 2.5D twin. 필지, target mass, 주변 context를 확인한다.

02

source_manifest

어떤 API/데이터/추정치를 썼는지, confidence와 제한을 남긴다.

03

QA Report

주소, 필지, 건물, texture, export gate 통과/실패 이유를 보여준다.

04

Export Package

static HTML, PDF, glTF/3D Tiles/CityGML 확장 경로를 제공한다.

제품 데모에서 보여줄 장면

주소 입력 결과가 공식 필지 위에 정렬되고, target building이 강조되며, 주변 context massing과 QA 상태가 같이 보인다.

  • 필지/PNU anchor
  • target footprint 기반 2.5D mass
